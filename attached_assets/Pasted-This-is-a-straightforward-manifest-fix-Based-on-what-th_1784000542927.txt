## The Fix

**Remove** the broad host permission (`<all_urls>` or `*://*/*`) from your manifest and replace it with just `activeTab`. The `robots.txt` and `llms.txt` fetch can be scoped dynamically using the `activeTab`'s domain at runtime — no static host permission needed.

**Your manifest `permissions` array should be:**

```json
{
  "permissions": [
    "activeTab",
    "storage",
    "tabs",
    "scripting",
    "sidePanel"
  ],
  "host_permissions": []
}
```

## One Code Change Needed

Wherever your background/service worker fetches `robots.txt` and `llms.txt`, make sure it retrieves the tab URL from the `activeTab` grant rather than from a stored or injected URL:

```javascript
// In your service worker / background script
chrome.action.onClicked.addListener(async (tab) => {
  const origin = new URL(tab.url).origin;
  const robotsUrl = `${origin}/robots.txt`;
  const llmsUrl = `${origin}/llms.txt`;
  // fetch(robotsUrl), fetch(llmsUrl) — works under activeTab grant
});
```

This change eliminates the broad host permission warning, removes the in-depth review flag, and makes your extension more approvable and more secure. [developer.chrome](https://developer.chrome.com/docs/extensions/whats-new)
