In the file server/routes.ts, find the section where scrapeWebsiteContent is called and its result is awaited. It currently has a .catch() handler that silently returns empty strings when scraping fails, like this:

ts
scrapingPromise.catch(err => {
  console.warn("Website scraping failed, using minimal signals", err.message)
  scrapingSucceeded = false
  return { html: "", text: "", sitemapUrls: [] as string[], discoveredSubdomains: [] as string[] }
})
The variable scrapingSucceeded is set to false but is never included in the API response, so the frontend has no idea scraping failed and displays a floored score as if it were real.

Make these three changes:

Change 1 — In the same .catch() block, add a scrapeError variable to capture the failure reason. Replace the existing catch block with:

ts
scrapingPromise.catch(err => {
  console.warn("Website scraping failed, using minimal signals", err.message)
  scrapingSucceeded = false
  scrapeErrorMessage = err.message || "Website could not be reached"
  return { html: "", text: "", sitemapUrls: [] as string[], discoveredSubdomains: [] as string[] }
})
And declare scrapeErrorMessage near where scrapingSucceeded is declared:

ts
let scrapingSucceeded = true
let scrapeErrorMessage: string | null = null
Change 2 — Find where the final audit response JSON is constructed and returned (the large object with auditResults, contentTopics, playbook, etc.). Add a scrapingStatus field to that response object:

ts
scrapingStatus: {
  success: scrapingSucceeded,
  warning: scrapingSucceeded ? null : "We could not fully scan your website. This may be because your site uses JavaScript rendering (React/Next.js), bot protection (Cloudflare), or was temporarily unreachable. Scores are estimated from available domain data and may not reflect your full content quality.",
  errorDetail: scrapeErrorMessage,
},
Change 3 — In the file client/src/components/audit-results.tsx, find the section near the top of the rendered output where signalQuality warnings are already shown (there is already a red warning card for auditData.signalQuality === "minimal"). Directly below that existing warning card, add this new scraping warning card:

tsx
{auditData.scrapingStatus && !auditData.scrapingStatus.success && (
  <Card className="bg-orange-600/20 border-2 border-orange-500 shadow-xl fade-in-up">
    <CardContent className="p-5 flex items-start space-x-4">
      <div className="bg-orange-500 rounded-full p-2 flex-shrink-0">
        <AlertTriangle className="h-6 w-6 text-primary-foreground" />
      </div>
      <div>
        <h3 className="text-base font-bold text-orange-500 mb-2">Limited Website Access</h3>
        <p className="text-sm text-foreground leading-relaxed">
          {auditData.scrapingStatus.warning}
        </p>
      </div>
    </CardContent>
  </Card>
)}
Also update the AuditData type in shared/schema.ts to include the new field. Find the auditData or AuditData interface/type and add:

ts
scrapingStatus?: {
  success: boolean;
  warning: string | null;
  errorDetail: string | null;
};
Do not change any other logic, scoring, or scraping behaviour. This fix only surfaces the existing failure state to the user — it does not change how scores are calculated.
