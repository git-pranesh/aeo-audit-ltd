## Step 2: Refactor Phase 1 — `/api/audit/analyze` (`server/routes.ts`)

Modify the `/api/audit/analyze` handler (`routes.ts:3375`) to run `scrapeWebsiteContent()` **BEFORE** making the `companyResearch` LLM call.

### Updated Flow for `/api/audit/analyze`:

```typescript
// server/routes.ts: inside app.post('/api/audit/analyze', ...)

// 1. Existing URL & DNS Validation
const targetUrl = sanitizeUrl(req.body.url);
await validateDns(targetUrl);

// 2. SCRAPE FIRST (Using your existing scraper-v2.ts)
let scrapedData;
try {
  scrapedData = await scrapeWebsiteContent(targetUrl);
} catch (scrapeErr) {
  console.warn(`[Phase 1] Scraping warning for ${targetUrl}:`, scrapeErr);
  scrapedData = { text: '', html: '' };
}

const pageText = scrapedData.text?.trim() || '';

// 3. IF NO CONTENT COULD BE SCRAPED
// Fallback: If scraping returns nothing, do NOT guess. Ask user or return minimal context.
if (!pageText || pageText.length < 100) {
  return res.json({
    warning: "Could not extract page text to determine business details.",
    industry: "Unknown",
    businessType: "Unknown",
    targetAudience: "Unknown",
    suggestedKeywords: [],
    suggestedCompetitors: [],
    scrapedSignal: "minimal"
  });
}

// 4. CLASSIFY WITH GROUNDED CONTENT
const antiHallucinationPrompt = `
You are a precise business intelligence extraction engine. Analyze ONLY the provided website content enclosed inside <scraped_content> tags.

<scraped_content>
${pageText.substring(0, 12000)} 
</scraped_content>

CRITICAL CONSTRAINTS:
1. Base ALL extracted fields ONLY on the text between the <scraped_content> tags.
2. Do NOT use prior external knowledge about this domain or brand.
3. NEVER infer industry, products, or services from the domain name or URL string.
4. For every claim, you MUST provide an "evidenceQuote" directly copied from the text.
5. If the content does not contain enough information to determine a field, set that field to "Unknown".

Return a valid JSON object matching this exact structure:
{
  "companyName": "Exact name found in text",
  "industry": "Specific industry (e.g., Interior Design, SaaS, Legal Services)",
  "businessType": "B2B | B2C | B2B2C",
  "targetAudience": "Primary customer segment identified in text",
  "evidenceQuote": "Exact 1-2 sentence snippet from the content that proves the industry/businessType",
  "suggestedKeywords": ["keyword1", "keyword2", "keyword3"],
  "suggestedCompetitors": ["competitor1", "competitor2"]
}
`;

const llmResponse = await llmCall({
  task: 'companyResearch',
  prompt: antiHallucinationPrompt,
  temperature: 0.1, // Low temperature for high adherence
  responseFormat: { type: "json_object" }
});

const companyIntel = JSON.parse(llmResponse);

// 5. Return confirmed details to client
return res.json({
  companyName: companyIntel.companyName,
  industry: companyIntel.industry,
  businessType: companyIntel.businessType,
  targetAudience: companyIntel.targetAudience,
  suggestedKeywords: companyIntel.suggestedKeywords || [],
  suggestedCompetitors: companyIntel.suggestedCompetitors || [],
  evidenceQuote: companyIntel.evidenceQuote || null,
  rawScrapedContent: pageText.substring(0, 2000) // Optional: cache/pass along to avoid re-scraping in Phase 2
});
```

## Step 3: Refactor Phase 2 — `/api/audit/batch` (`server/routes.ts`)

Currently (`routes.ts:3704`), Phase 2 runs `scrapeWebsiteContent()`, `companyIntelligencePromise`, and `competitorAnalysisPromise` in a parallel `Promise.all`.

If the user modified or confirmed details in Phase 1, Phase 2 already uses the confirmed data. However, if Phase 1 was skipped or re-run in Phase 2, **break the parallel lock and pass scraped content sequentially.**

### Updated Flow for `/api/audit/batch`:

```typescript
// server/routes.ts: inside app.post('/api/audit/batch', ...)

// 1. STEP ONE: SCRAPE WEBSITE (AWAIT FIRST)
const scrapeResult = await scrapeWebsiteContent(targetUrl);

// 2. STEP TWO: RUN INTEL & COMPETITORS IN PARALLEL (USING SCRAPED RESULT)
const userProvidedContext = req.body.confirmedCompanyContext;

let companyIntelPromise;
if (userProvidedContext && userProvidedContext.industry !== 'Unknown') {
  // Happy Path: Use confirmed context from Phase 1
  companyIntelPromise = Promise.resolve(userProvidedContext);
} else {
  // Fallback Path: Classify using the freshly scraped text
  companyIntelPromise = llmCall({
    task: 'companyResearch',
    prompt: buildGroundedIntelPrompt(scrapeResult.text),
    temperature: 0.1
  }).then(res => JSON.parse(res));
}

let competitorAnalysisPromise;
if (req.body.confirmedCompetitors?.length > 0) {
  competitorAnalysisPromise = llmCall({
    task: 'competitorAnalysis',
    prompt: buildCompetitorPrompt(scrapeResult.text, req.body.confirmedCompetitors)
  });
} else {
  competitorAnalysisPromise = llmCall({
    task: 'companyResearch',
    prompt: buildCompetitorDiscoveryPrompt(scrapeResult.text)
  });
}

// 3. AWAIT DOWNSTREAM AI TASKS
const [companyIntel, competitorAnalysis] = await Promise.all([
  companyIntelPromise,
  competitorAnalysisPromise
]);

// Proceed with scoring, topic generation, and Firestore persistence...

```

## Summary of Benefits After This Refactor

1. **Bug Permanently Fixed:** Domain names like `pressense.co` will never trigger false keyword assumptions (like "printing/PR") because the model is bounded strictly by `<scraped_content>` tags and forced to produce an `evidenceQuote`.
2. **~90% Lower LLM Cost in Phase 1:** You no longer need Perplexity Sonar ($3–$15 / 1M tokens + per-search fee) for Phase 1 company details. DeepSeek V4 Flash ($0.14–$0.28 / 1M tokens) gets the job done cleanly because the context is supplied directly.
3. **Zero New NPM Dependencies:** Leverages your existing `server/scraper-v2.ts` (Firecrawl/Jina cascade) and `server/llm-router.ts` (`llmCall` abstraction).
